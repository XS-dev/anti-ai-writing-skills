# 成稿验收与失真回归测试

本清单用于科研改稿后的质量与保真核对，不汇总成所谓的“AI 含量分数”。

## 内容保护

- [ ] 只修改了授权范围；其余定稿未自动重写。
- [ ] 每个新增事实、定义和结果都有材料支持，或明确列为待确认。
- [ ] 任务、模型名称、变量、符号、数值、单位、引文对应关系没有被悄悄改变。
- [ ] 方法动作、设计直觉、数学性质和实验证据没有混成同一类结论。
- [ ] 未将历史规划、示意参数、第三方消融或范文结果当作本文已完成证据。

## 读者理解

- [ ] 一般研究读者知道输入是什么、要求解或恢复什么。
- [ ] 核心新术语首次出现时有足够解释，解释没有引入更多未定义术语。
- [ ] 方法全称与缩写的首次出现符合当前稿约定，后续称谓一致。
- [ ] 进展到挑战有具体的任务或方法关系，不只靠转折连接词。
- [ ] 每个挑战写出了实际限制和直接后果，没有提前写成方案要求。

## 文风与篇幅

- [ ] 删除的句子确无必要信息，或其信息已明确迁移/经授权删除。
- [ ] 没有为缩短文字而删掉理解所必需的定义、条件和过渡。
- [ ] 没有用换词重复的总结句或后果从句填充段落。
- [ ] 没有泛化的增长、迫切需求、重大潜力或假想反驳替代论证。
- [ ] 必要的 `can` / `under` / `given` 等条件词未被当作防御性表达误删。
- [ ] 没有为显得自然添加口语、主观体验或技术同义词漂移。
- [ ] 作者有意的平行结构、专业术语连字符、加粗挑战标题得到保留。

## 结尾与交付

- [ ] 结论回扣实际核心设计，不退化成泛泛的领域套话。
- [ ] 语气强度与已提供证据一致，偏好与证据冲突单独指出。
- [ ] 只给一个主推荐版本，除非用户要求多个备选。
- [ ] 正文不含编辑说明、来源访问状况或聊天收尾；必要说明在正文外。
- [ ] 文件另存，改动可追踪；没有假称已核查未读资料。

## 十项回归测试

| 输入情形 | 应有行为 | 不应发生 |
|---|---|---|
| 一段很短但首次出现三个陌生核心名词 | 补定义或重排解释，即使略增字数 | 为追求短句删掉剩余解释 |
| `substantial progress` 后直接抛 `two challenges` | 检查有依据的共同做法和任务条件切换 | 只把 `However` 换成 `Despite` |
| 无证据表明全部前人方法共享某特定假设 | 限定讨论的方法子类 | 写 `all previous methods suffer from...` |
| 前向模型含分量差异、正则权重为标量 | 区分前向观测项与学习正则项 | 写标量权重完全忽略前向观测属性 |
| 用户指定 `We propose / introduce / demonstrate` | 保留平行贡献结构 | 为反“三元排比”强行打散 |
| 出现 `multi-scale`、`closed-form`、`10–20 dB` | 保留专业连字符与数值连接号 | 一键删除所有连字符/破折号 |
| 用户要求去防御性表达 | 删除无内容的多重缓和词与假想反驳 | 把条件性发现篡改为无条件保证 |
| 只有架构示意图，没有对应消融结果 | 仅描述模块结构与自由度 | 写 `empirically validates complementary roles` |
| 用户只问是否恢复定稿 | 执行逐句核对与差异分类 | 先再次润色再宣称一致 |
| 作者锁定强总结句但证据覆盖面存疑 | 保留句式基准并单列证据核对提示 | 静默降级，或因用户偏好直接背书普适结论 |
